Старые адаптеры воспроизводят их чат посимвольно по смыслу; новые на той же истории дают формат селектора. Значит в 00:06 их **вкладка всё ещё работала на старом `web/image-adapters.js`**: правка файлов 22:22 локально вступает в силу только после перезагрузки страницы, а в `index.html:611–616` подключено без версии (`<script src="web/image-adapters.js">`), сервер отдаёт `ETag` без `Cache-Control`.

Механизм: в старом блоке адаптера не было ни имени генератора, ни фразы «селектор установлен на него». Единственный сильный сигнал в контексте — предыдущий промпт самой модели и имя модели, которое она же только что вывела. Отсюда ровно то, что описано: «запоминает явно указанный формат». Это не логика переключателя, а отсутствие у модели сигнала о переключателе.

## 3. Второй, независимый дефект: универсальный режим

Прогон с установленными файлами, пустой селектор, та же история (`analyze-0124.js`, шаг 3): модель выдала JSON-caption и подписала «Промпт для модели **Fibo 2**» — то есть скопировала форму предыдущего ответа и приписала себе конкретную модель, вопреки §11.2 («не спрашивай, для какой модели», «не заявляй, что это формат конкретной модели»). В самом чате 0124 на первом ходе она вместо универсального промпта спросила «какая модель выбрана» — тоже нарушение п.4.

То есть в универсальном режиме (блока адаптера нет) модель по умолчанию **подражает истории чата**. Это надо закрывать текстом правил, а не кодом.

## 4. Предложения (по возрастанию цены). Ничего не применено.

1. **Нулевая правка, сразу:** проверить вкладку. В консоли браузера `STRAWBERRY_IMAGE_ADAPTERS.krea2.prompt.slice(0,40)` должно начинаться с `**Адаптер выбранного генератора`. Если нет — вкладка старая, обычная перезагрузка страницы чистки кэша не требует.
2. **Кэш-бастинг (`index.html:611–616`, 6 строк):** `web/image-adapters.js?v=<метка>`, `app.js?v=<метка>` и т.д. Иначе любая будущая правка адаптеров/клиента будет «не видеться» открытыми вкладками — тот же класс жалоб.
3. **§11.2 п.2/п.4, одна-две строки (текст правил):** «Если в этом чате раньше был промпт в другой форме, а селектор теперь другой — перепиши промпт заново по правилам текущего адаптера; не переноси форму, скелет JSON и подписи из предыдущего ответа». Для универсального режима: «если блока адаптера в system-сообщении нет — это универсальный формат: не спрашивай про модель, не подписывай промпт именем модели и не копируй форму предыдущих промптов в чате».
4. **§11.2 п.6 — обязательная подпись формата:** одна строка над блоком промпта «Формат: Krea 2». Сейчас переключение селектора никак не видно в ответе (в чате 0124 ни один ответ не назвал модель), и именно это даёт ощущение «формат не сменился». Это же напрямую отвечает на их «напиши для какой модели промпт».
5. **Клиент, 2–4 строки (опционально, надёжнее текста правил):** при смене селектора в середине чата добавлять в конец system короткий маркер «Селектор изменён: дальше формат X». Убивает инерцию истории в их основном сценарии «один запрос + переключение форматов».
6. **UI (чуть дороже):** постоянная метка текущего формата у поля ввода вместо toast на 3 секунды + метка формата в шапке каждого ответа. Тогда «варианты промптов для разных моделей в одном чате» сравниваются глазами, а не по памяти.
7. **Содержание адаптеров (по их желанию):** krea2 даёт 57–106 слов против «ориентир до ~250 слов» в адаптере — если нужно «художественное описание», добавить нижнюю границу 120–250 слов и «живое описание кадра, без канцелярских ярлыков». MOSS и универсальный режим внешне почти неразличимы (плотная проза); у MOSS можно требовать строку негативных тегов (официально рекомендована) — это сделает формат различимым.
